# Upgrading to 0.24

0.24 is 0.22's API with a faster reactive engine. 0.23's closed surface is withdrawn: an app on 0.22 upgrades with no code change, and an app on 0.23 goes back to 0.22's API.

## From 0.22

Nothing to change. What is new is the engine, and two options you may take:

- **Subscriptions** are filed by table and row id, and grouped: callers of one query with the same args and the same view share one run. A pass judges only what a write can reach, and writes queued on the storage invalidate in one pass.
- **`ctx.db.sqlOver(tables, sql, ...params)`** is a raw read held to the rows of the tables it names.
- **`evaluation: { workers, module, setup }`** runs subscriptions' re-runs off the main thread, in a pool of read-only engines built by `setup`. It is opt-in; leave it out and nothing changes.
- **`jobScheduler: "none"`** arms no jobs or timers.

## From 0.23

0.23's rules are gone: TypeBox args and columns, `ctx.scheduler`, `ctx.env`/`ctx.services`, `ctx.query`, `purityCheck`, `ReentryError`, plugins by module, and `evaluation: { workers, offloadAboveMs }`. Code written for 0.23 that only used what 0.22 also had runs unchanged; code that used them returns to 0.22's forms.
